1. Project Overview

This project focuses on automated UI testing of a Task Manager web application using Selenium WebDriver with Java.

The main objective is to verify the functionality, usability, and validation behavior of the application's user interface through automated test cases.

The testing covers user registration, email and password validation, task creation, task editing, task deletion, task status management, and task creation cancellation.

7.1 TC-001 – Email Validation Without @

Objective: Verify that the registration form rejects an email address without the "@" symbol.

Test Data: "harshigmail.com"

Expected Result: The application should prevent submission and display an email validation message.

Actual Result: The browser's HTML5 email validation rejected the invalid email address.

Status: PASS

7.2 TC-002 – Email Without .com

Objective: Verify the application's email validation behavior when an email address does not contain ".com".

Test Data: "harshi@gmail"

Expected Result: The application should reject the email address if it does not meet the application's email validation rules.

Actual Result: The browser accepted the input format, but the backend rejected the registration with an email validation error.

Status: PASS

7.3 TC-003 – Password Length Boundary Test

Objective: Verify password validation by testing different password lengths during registration.

Test Data:

Test Input| Password Length| Actual Result
Password 1| 5 characters| Rejected
Password 2| 6 characters| Accepted
Password 3| 7 characters| Accepted
Password 4| 11 characters| Accepted
Password 5| 12 characters| Accepted
Password 6| 13 characters| Accepted

Expected Result: Passwords should be accepted or rejected according to the application's specified minimum and maximum password-length requirements.

Actual Result: A 5-character password was rejected. Passwords containing 6, 7, 11, 12, and 13 characters were accepted.

Status: REVIEW REQUIRED

Observation: The observed minimum accepted length appears to be 6 characters. However, the maximum password length has not been established. The application requirements must be checked before classifying this behavior as a defect.

7.4 TC-004 – Task Name Length Boundary Test

Objective: Verify task-name validation using values around the assumed minimum and maximum boundaries.

Test Data:

Test Input| Length| Assumed Expected Result| Actual Result
AB| 2| Rejected| Accepted
ABC| 3| Accepted| Accepted
ABCD| 4| Accepted| Accepted
A repeated 49 times| 49| Accepted| Accepted
A repeated 50 times| 50| Accepted| Accepted
A repeated 51 times| 51| Rejected| Accepted

Actual Result: All six task names were accepted.

Status: PARTIAL / REVIEW REQUIRED

Observation: The expected 3–50 character boundary was an assumption during testing. Confirm the actual application requirements before reporting the acceptance of 2- and 51-character task names as defects.

7.5 TC-005 – Move Task Button

Objective: Verify that a task can be moved from the Pending column to the In Progress column.

Expected Result: The task should move successfully to the In Progress column.

Actual Result: The task was successfully moved from Pending to In Progress.

Objective: Verify that a user can cancel task creation without saving the task.

9. Running Selenium Tests

Prerequisites

Install and configure:

- JDK 21
- IntelliJ IDEA
- Apache Maven
- Google Chrome
- Selenium and JUnit dependencies

Step 1 – Start the Application

Download the application source code:

"Task Manager GitHub Repository" (https://github.com/ArunPragas2001/TaskManager)

Run the application locally and verify that it is accessible at:

http://localhost:8000

Step 2 – Open the Selenium Project

Open the Selenium project in IntelliJ IDEA.

Step 3 – Run All Tests

Open the terminal in the project directory and execute:

mvn clean test

Step 4 – Run an Individual Test

Example:

mvn -Dtest=TC005_MoveTaskButtonTest test

mvn -Dtest=TC008_TaskStatusDisplayTest test

mvn -Dtest=TC009_TaskCreationCancelTest test

Step 5 – View Test Reports

Maven Surefire generates test reports inside:

target/surefire-reports/

Review the generated reports to check test execution results.
